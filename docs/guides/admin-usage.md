# 管理后台使用记录

管理员在侧栏“使用记录”中核对用户、模型和逐笔请求的消耗。统计来自
`coincoin_request_logs`，沿用现有请求日志和计费口径，需要管理员令牌。

## 查询和下钻

1. 选择时间范围，填写可选的用户名、邮箱、用户 ID 或模型名称，点击“查询 / 刷新”。
2. 用户排行支持按净消耗、Tokens、请求数、图片或视频排序，每页 20 条。
3. 点击用户名进入该用户的模型消耗，再点击模型查看该用户、该模型的逐笔请求。
   顶部条件按钮可以单独取消下钻；“重置筛选”恢复今天、全部用户和模型。
4. 在“请求明细”点击“详情”，核对输入/输出 Tokens、缓存、图片/视频、用户扣费、
   耗时、渠道、fallback、上游请求 ID 和日志中保存的计费倍率、单价、价格版本。
5. 需要对账时导出 CSV。导出沿用**已查询**的筛选条件和查询截止时间，最多 10,000 条；
   超限会明确报错，不会静默截断。CSV 带 UTF-8 BOM 并转义公式前缀。

更多筛选支持接口、API Key ID（非明文密钥）和渠道 ID。模型文本搜索匹配客户别名、
请求模型、上游模型和计费 SKU；从模型行下钻使用客户模型精确匹配。

## 时间与统计口径

| 范围 | 边界 |
| --- | --- |
| 今天 | 上海时区当天 00:00 至查询时间 |
| 近 24 小时 | 查询时间向前 24 小时 |
| 昨天 | 上海时区昨天 00:00 至今天 00:00 |
| 近 3 天 / 近 7 天 / 近 30 天 | 向前滚动 72 / 168 / 720 小时 |
| 本周 | 上海时区本周一 00:00 至查询时间 |
| 本月 | 上海时区本月 1 日 00:00 至查询时间 |
| 自定义日期 | 含结束当天，最多 93 天；尚未结束的日期截到查询时间 |

所有查询采用开始时间包含、结束时间不包含的边界。趋势在两天以内按小时，
更长范围按天，空桶补零；可切换净消耗、Tokens 和请求数，负净消耗展示退款冲减。

- 净消耗：沿用管理后台口径，使用非零 `retail_charge_cents`，否则回退到
  `cost_cents`，单位美分，页面显示美元；保留退款负值，不代表上游采购成本。
- 总 Tokens = 输入 + 输出。输入已包含缓存用量；缓存读取和写入单独展示，不能再次
  加入总量。读取字段为非零 `cache_read_tokens`，否则回退到兼容字段 `cached_tokens`。
- 请求数排除视频退款记录和负扣费记录；成功为 200–399，失败为 ≥400。
  失败率使用请求数作分母，无请求时显示“—”。这是日志中的请求状态。
- 退款计入日志记录数、净消耗和退款总额，不计入请求数、成功/失败数或平均耗时。
- 平均耗时仅包含非退款且 `duration_ms > 0` 的记录。Fallback 次数统计
  `route_attempt > 0` 的请求，不等同于额外 HTTP 调用总数。
- 活跃用户和模型数是当前过滤范围内日志的去重数，含只有退款记录的用户或模型。
  模型按 `customer_model_alias`、`model`、未记录模型的顺序归类。
- 图片/视频使用日志中的净数量，含负值冲减，不转换成 Tokens。
- 历史日志没有保存的详情不能补算为真实历史数据；零值也可能是旧字段默认值。

页面固定 `as_of`，翻页和导出使用相同时间边界。请求日志异步落库，迟到日志仍可能
改变同一范围的结果，这不是数据库历史快照。页面展示更新时间，刷新后重新查询。

## 性能与验证

- 总览和当前表格分开按需加载，每页只渲染 20 行，不下载全部用户或请求。
- 首次进入使用记录发 2 个请求：总览（2 条 SQL）和当前排行（1 条 SQL）。
  排行 / 明细复用总览计数，使用 `include_total=false` 避免再次扫描计数。
- 趋势 SQL 仅聚合金额、Tokens 和请求数，不重复计算按桶去重用户、模型及延迟。
  独立调用排行需要总数时使用 `COUNT(DISTINCT ...)`，不重复全部聚合。
- 同一次查询最多缓存 16 个表格结果，30 秒有效，仅存当前页面内存；更换管理员令牌、
  修改查询或手动刷新会清空。短时间返回用量页面保留已加载内容。
- 连续切换时间 / 结果筛选合并为 180ms 防抖；切换查询、离开页面会中止浏览器等待，
  且通过版本检查阻止旧响应覆盖新数据。浏览器取消不保证已经执行的 SQL 同步停止。
- 查询直接约束 `created_at` 时间范围，复用现有时间及用户时间索引；不新增迁移。
  模糊模型搜索、聚合排序及深分页仍需扫描范围内数据，生产性能应基于真实数据量测量。
- CSV 限量加载，格式化在线程池完成，避免大量字符串处理阻塞 API 事件循环。
- 管理后台重复点击当前导航不再重发查询；移除整个长页面切换缩放动画和统计卡片背景模糊，
  沿用主分支已有的普通卡片优化；手机表格在容器内部横向滚动。

自动回归见 `tests/test_admin_usage_analysis.py`，覆盖时间边界、真实 SQL 聚合、退款、
筛选一致性、分页、导出、权限及避免重复计数。测试采用隔离 SQLite，模拟 MySQL 的
两个时间函数，不替代真实 MySQL 查询计划和生产容量测试。

前端异步回归执行 `node --test tests/admin_usage_ui.test.cjs`，覆盖防抖期间离开页面、
返回缓存页面及旧响应晚到；使用 Node 20 或更新版本。

## 故障排查

- 令牌失效：重新连接管理员令牌后查询；接口均要求管理员鉴权。
- 无记录：扩大时间范围、取消用户 / 模型条件，并确认日志已经异步写入。
- CSV 超过 10,000 条：缩小时间、筛选用户或模型后再导出。
- 数字与财务流水不一致：先确认时间范围、退款和统计单位；此页核对请求日志，
  财务流水含充值、赠送等其它事件。不要把用户消耗当成供应商成本。

## 接口

- `GET /admin/usage/overview`：总览、趋势及统计时间边界。
- `GET /admin/usage/groups`：按用户 / 模型聚合、排序、分页，可省略总数查询。
- `GET /admin/usage/users/{user_id}/models`：用户模型聚合，沿用公共过滤条件。
- `GET /admin/usage/records`：请求详情分页，可省略总数查询。
- `GET /admin/usage/export.csv`：相同过滤口径的请求 CSV。

旧的 `GET /admin/usage/daily`、`GET /admin/usage/leaderboard` 和用户请求日志接口保留。
